# Нерабочие даты

Блок «Нерабочие даты» на экране «График работы»: специалист отмечает разовые
дни вне недельного графика (отпуск, больничный). Недельный график
(`/api/work-schedules/`) при этом не меняется.

Все запросы авторизованные (Bearer), ключи в camelCase. Даты — `YYYY-MM-DD`.
Отметить можно только сегодняшнюю или будущую дату, не дальше 366 дней вперёд.

## Список — `GET /api/non-working-dates/`

Только предстоящие даты (начиная с сегодня), по возрастанию, без пагинации.

```json
[
  {"id": 12, "date": "2026-10-05"},
  {"id": 13, "date": "2026-10-06"}
]
```

## Сохранить выбор из календаря — `PUT /api/non-working-dates/sync/`

Рекомендуемый вариант для кнопки «Сохранить»: передаётся полный список
выбранных дат, сервер заменяет им все предстоящие даты. Прошедшие даты не
трогаются. Дубли в запросе схлопываются, до 100 дат за раз; пустой список
снимает все предстоящие отметки.

```json
{"dates": ["2026-10-05", "2026-10-06", "2026-10-07"]}
```

Ответ `200 OK` — актуальный список в формате `GET`.

## Точечные изменения

- `POST /api/non-working-dates/` с `{"date": "2026-10-05"}` — отметить дату.
  `201 Created` для новой, `200 OK` если дата уже была отмечена (дубль не создаётся).
- `DELETE /api/non-working-dates/{id}/` — снять отметку, `204 No Content`.

Ошибки валидации — `400` со стандартным телом, например
`{"date": ["Нельзя отметить прошедшую дату."]}`.

## Где ещё приходят даты

- `GET /api/specialists/{id}/` — поле `nonWorkingDates` (только предстоящие),
  чтобы клиент видел, что специалист в эти дни не работает.
- WebSocket чата, событие `user_update` — поле `non_working_dates` рядом со
  `schedule`; при изменении дат в `changes` приходит `"non_working_dates"`.
