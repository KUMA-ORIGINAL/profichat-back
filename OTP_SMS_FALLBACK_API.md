# Отправка OTP: WhatsApp + фолбэк на SMS

Инструкция для клиентского приложения (Flutter / web).

## Как работает

По умолчанию код подтверждения приходит **в WhatsApp** (сценарий `otp`).
Если код не пришёл, пользователь нажимает «Код не пришёл — отправить по SMS»,
и приложение повторяет тот же запрос с `channel: "sms"` (сценарий `otp_sms`).

Важно: при отправке по SMS бэкенд **переотправляет тот же самый код**, если предыдущий
ещё жив (не подтверждён и не просрочен, срок жизни кода — 5 минут). Новый код не выдаётся,
поэтому пользователь может ввести код из любого сообщения — из WhatsApp или из SMS.

## Эндпоинт

```
POST /api/auth/sms/send/
Content-Type: application/json
```

Авторизация не требуется.

### Тело запроса

| Поле            | Тип    | Обяз. | Описание                                                            |
|-----------------|--------|-------|---------------------------------------------------------------------|
| `phone_number`  | string | да    | Номер в международном формате, например `+996700000000`             |
| `channel`       | string | нет   | `whatsapp` (по умолчанию) или `sms`                                 |
| `app_signature` | string | нет   | Подпись приложения для SMS Retriever API (Android). Нужна для `sms` |

WhatsApp (первая отправка):

```json
{ "phone_number": "+996700000000", "app_signature": "AbC123xyz==" }
```

SMS (нажали «код не пришёл»):

```json
{ "phone_number": "+996700000000", "app_signature": "AbC123xyz==", "channel": "sms" }
```

### Ответы

**201 Created** — код отправлен:

```json
{ "message": "Код подтверждения отправлен", "channel": "whatsapp" }
```

```json
{ "message": "Код подтверждения отправлен по SMS", "channel": "sms" }
```

Поле `channel` показывает, каким каналом фактически ушёл код — используйте его
в тексте подсказки на экране ввода кода («Код отправлен в WhatsApp» / «Код отправлен по SMS»).

**429 Too Many Requests** — слишком часто:

```json
{ "error": "Код уже был отправлен недавно. Подождите минуту.", "seconds_left": 42 }
```

```json
{ "error": "SMS уже было отправлено недавно. Подождите минуту.", "seconds_left": 42, "channel": "sms" }
```

`seconds_left` — сколько секунд осталось; используйте для таймера на кнопке.

**400 Bad Request** — ошибки валидации полей (стандартный формат DRF).

**500 Internal Server Error** — не удалось отправить код:

```json
{ "error": "Не удалось отправить код подтверждения" }
```

### Кулдауны

Два независимых таймера на один номер:

- **60 секунд** — на выдачу нового кода (обычная кнопка «Отправить код ещё раз»);
- **60 секунд** — отдельно на переотправку по SMS.

Поэтому сразу после отправки в WhatsApp кнопка «Код не пришёл, отправить по SMS» **работает**,
не дожидаясь общего таймера. Повторное нажатие той же SMS-кнопки — уже через минуту.

## Проверка кода

Эндпоинт проверки не изменился — код из WhatsApp и код из SMS проверяются одинаково:

```
POST /api/auth/sms/verify/
{ "phone_number": "+996700000000", "code": "1234" }
```

Ответ: `{ "refresh": "...", "access": "...", "stream_token": "..." }`.

## Рекомендуемый сценарий в UI

1. Пользователь вводит номер → `POST /auth/sms/send/` без `channel` (уйдёт в WhatsApp).
2. Экран ввода кода: таймер на 60 сек + подпись «Код отправлен в WhatsApp».
3. Кнопка **«Код не пришёл — отправить по SMS»** доступна сразу (можно показать через 10–15 сек,
   чтобы не отвлекать) → тот же запрос с `channel: "sms"`.
4. После успеха — подпись меняется на «Код отправлен по SMS», кнопка SMS блокируется на 60 сек.
5. При 429 — блокируем соответствующую кнопку на `seconds_left` секунд, показываем `error`.

## Про `app_signature` (Android)

`app_signature` — 11-символьный хеш приложения для
[SMS Retriever API](https://developers.android.com/identity/sms-retriever/overview);
он подставляется в конец текста SMS, чтобы Android автоматически подставил код без
разрешения на чтение SMS. Передавайте его в каждом запросе (в WhatsApp-сценарии он
игнорируется). На iOS и web поле можно не передавать.
