# Push-уведомления: статус доставки

Инструкция для клиентского приложения (Flutter).

## Проблема, которую это решает

Раньше бэкенд считал push доставленным, даже если FCM отклонял токен: библиотека
`django-push-notifications` шлёт сообщения через `messaging.send_each()`, который
**не бросает исключение** при отказе — ошибка лежит внутри ответа. Отказ никуда не
попадал, `Notification.pushed_at` проставлялся, и ни сервер, ни приложение не знали,
что уведомление не дошло.

Теперь ответ FCM разбирается: неуспешная отправка фиксируется с кодом ошибки,
мёртвый токен деактивируется, а приложение может спросить статус.

## Эндпоинт

```
GET /api/push/status/
Authorization: Bearer <access_token>
```

### Ответ 200

```json
{
  "pushEnabled": false,
  "reason": "token_invalid",
  "message": "Токен устройства недействителен, зарегистрируйте его заново",
  "action": "reregister_token",
  "activeDevices": 0,
  "totalDevices": 1,
  "lastSuccessAt": "2026-08-01T10:15:00+06:00",
  "lastFailureAt": "2026-08-19T09:00:00+06:00",
  "lastErrorCode": "UNREGISTERED"
}
```

| Поле            | Описание                                                                 |
|-----------------|--------------------------------------------------------------------------|
| `pushEnabled`   | `true` — пуши доходят; `false` — не дойдут или последняя отправка упала   |
| `reason`        | Машинная причина, см. таблицу ниже                                        |
| `message`       | Готовый текст на русском, можно показать пользователю                     |
| `action`        | Что делать приложению: `reregister_token`, `retry_later` или пусто        |
| `activeDevices` | Сколько живых устройств привязано к пользователю                          |
| `totalDevices`  | Всего устройств, включая деактивированные                                 |
| `lastSuccessAt` | Когда последний раз push реально ушёл (может быть `null`)                 |
| `lastFailureAt` | Когда последний раз отправка провалилась (может быть `null`)              |
| `lastErrorCode` | Код ошибки FCM последней неудачи                                          |

### Значения `reason`

| `reason`         | Что значит                                       | Что делать приложению                              |
|------------------|--------------------------------------------------|----------------------------------------------------|
| `ok`             | Последняя отправка прошла                        | Ничего                                             |
| `no_devices`     | Токен ни разу не регистрировался                 | Запросить разрешение и вызвать `POST /api/register-fcm/` |
| `token_invalid`  | Все токены деактивированы (протухли)             | Получить новый FCM-токен и заново `register-fcm`    |
| `provider_error` | Последняя отправка упала на стороне FCM/APNs     | Показать баннер, повторить проверку позже           |
| `unknown`        | Устройство есть, отправок ещё не было            | Ничего                                             |

### Коды `lastErrorCode`

| Код                     | Причина                                                                 |
|-------------------------|-------------------------------------------------------------------------|
| `UNREGISTERED`          | Токен больше не действителен: приложение переустановили/очистили данные  |
| `SENDER_ID_MISMATCH`    | Токен выдан другим Firebase-проектом (перепутаны `google-services.json`) |
| `INVALID_ARGUMENT`      | Некорректный токен или payload                                           |
| `THIRD_PARTY_AUTH_ERROR`| Проблема с APNs-ключом/сертификатом (iOS)                                |
| `QUOTA_EXCEEDED`        | Превышены лимиты отправки                                                |
| `UNAVAILABLE`, `INTERNAL` | Временная проблема FCM — можно повторить                               |
| `NO_DEVICES`            | Нет активных устройств                                                   |

Первые три и `SENDER_ID_MISMATCH` приводят к деактивации устройства — после них
`activeDevices` станет `0` и потребуется перерегистрация токена.

## Рекомендуемый сценарий в UI

1. При старте (и после возврата из фона) — `GET /api/push/status/`.
2. `reason == "no_devices"` или `"token_invalid"` → получить свежий токен через
   `FirebaseMessaging.instance.getToken()` и отправить в `POST /api/register-fcm/`,
   затем перепроверить статус.
3. `reason == "provider_error"` → баннер «Уведомления временно не приходят»,
   перепроверить позже.
4. Отдельно проверяйте системное разрешение на уведомления в самой ОС — бэкенд его
   не видит, для него устройство с отключёнными уведомлениями выглядит рабочим.
5. Не полагайтесь на пуш как на единственный канал: историю уведомлений всегда можно
   подтянуть через `GET /api/notifications/`.

## Регистрация токена

Без изменений:

```
POST /api/register-fcm/
{ "registrationId": "<FCM token>" }
```

Повторная регистрация того же токена снова делает устройство активным.
Токен стоит переотправлять при каждом запуске приложения и на
`FirebaseMessaging.instance.onTokenRefresh`.
