# «Вы врач из ErkinAI?» — инструкция для Flutter

Человек регистрируется в ProfiChat и подтверждает номер по SMS. Если этот номер
известен ErkinAI как карточка сотрудника, приложение предлагает стать
специалистом и предзаполняет анкету данными CRM.

Всё общение с ErkinAI идёт через бэкенд ProfiChat. **Приложение в ErkinAI не
ходит** и секретов интеграции не хранит — только два вызова к своему API.

```
① POST /api/auth/sms/verify/        → в ответе erkinaiSpecialistOffer
② GET  /api/organizations/          → список клиник (если нужен выбор)
③ POST /api/auth/erkinai/become-specialist/
```

---

## ① Предложение приходит в ответе на вход

Ничего нового звать не надо: поле добавилось в существующий
`POST /api/auth/sms/verify/`.

```json
{
  "refresh": "...",
  "access": "...",
  "streamToken": "...",
  "erkinaiSpecialistOffer": [
    {
      "id": 52,
      "fullName": "Юлдашева Зарифа Мажитовна",
      "phone": "+996709556597",
      "email": "",
      "photoUrl": null,
      "specialties": ["Урогинеколог-нейролог"],
      "primarySpecialty": "Урогинеколог-нейролог",
      "clinicalRole": "doctor",
      "experienceYears": null,
      "bio": "",
      "education": "",
      "languages": [],
      "consultationType": null,
      "gender": null,
      "hasCrmAccount": true,
      "organization": {"id": 4, "slug": "klinika-21", "name": "Клиника 21"},
      "branch": {"id": 14, "slug": "21", "name": "Клиника 21"}
    }
  ]
}
```

`[]` — предлагать нечего: карточки нет, человек уже специалист, или ErkinAI
недоступен. Приложению эти случаи различать не нужно — пусто значит обычная
регистрация без единого упоминания CRM.

Поле приходит **при каждом входе**, не только при первой регистрации. Тот, кто
завёлся до появления фичи или раньше отказался, увидит предложение снова.

### Ничего не считать заполненным намертво

Почти все поля могут быть пустыми (`""`, `null`, `[]`) — в примере выше так и
есть. Это предзаполнение: человек правит любое поле перед сохранением, вёрстка
должна переживать пустоту без плейсхолдеров вида «null».

## ② Экран подтверждения

**Одна карточка** — основной случай:

> **Вы Юлдашева Зарифа Мажитовна?**
> Урогинеколог-нейролог, «Клиника 21»
> [ Да, это я ] [ Нет, я обычный пользователь ]

Кнопка «нет» **обязательна**. Номера операторы перевыпускают: новый владелец
номера уволившегося врача не должен молча получить его имя, образование и
клинику. Никакой автоматической выдачи роли без явного нажатия.

**Несколько карточек** — человек работает в двух организациях. Бэкенд намеренно
не выбирает за него: покажите список, дайте выбрать одну. Порядок стабильный.

### Выбор клиники

`organization` внутри карточки — это организация **в ErkinAI**, и привязкой она
не является. Клинику человек выбирает из справочника ProfiChat:

```
GET /api/organizations/?search=Клиника
```

Обычный постраничный список активных организаций (авторизация не нужна).
Название из `card.organization.name` используйте, чтобы подставить его в поиск
или подсветить нужный пункт — «в CRM вы числитесь в „Клиника 21“».

Если подходящей клиники в списке нет — дайте пропустить шаг. Роль выдаётся и
без организации, указать её можно позже в профиле.

### Чем заполнять анкету

| Поле профиля | Откуда |
|---|---|
| Фамилия / Имя / Отчество | `fullName`, разбирается как «Фамилия Имя Отчество» |
| Аватар | `photoUrl` (может быть `null`) |
| Специализация | `primarySpecialty`; весь список — `specialties` |
| Стаж | `experienceYears` |
| О себе | `bio` |
| Образование | `education` |
| Языки | `languages` |
| Формат приёма | `consultationType`: `in_person` / `online` / `both` |
| Пол | `gender`: `male` / `female` |

Бэкенд при принятии карточки заполнит эти поля **сам** — но только пустые:
всё, что человек уже написал о себе, остаётся как было.

## ③ Принять карточку

```
POST /api/auth/erkinai/become-specialist/
Authorization: Bearer <access из шага ①>
Content-Type: application/json

{"employeeId": 52, "organizationId": 7}
```

`organizationId` необязателен — пропустите, если клинику не выбрали.

Ответ `200`:

```json
{"role": "specialist", "organizationId": 7, "employeeId": 52}
```

После этого перечитайте `GET /api/users/me/` — профиль уже заполнен.

| Код | Что случилось | Что делать в приложении |
|---|---|---|
| `400` | не передан `employeeId`, либо `organizationId` не число | баг клиента |
| `401` | протух access-токен | обновить штатным refresh и повторить |
| `404` | карточки с таким id по телефону этого пользователя нет **или** выбранной организации не существует / она отключена | перечитать предложение и список клиник; повтор с тем же телом не поможет |

Тело ошибки — общий формат ProfiChat: `{"code": "...", "message": "..."}`.
Ветвитесь по `code` / HTTP-статусу, не по тексту.

Бэкенд не верит присланному `employeeId`: он заново ищет карточки по телефону
авторизованного пользователя и принимает только совпавшую. Так что подставить
чужой id и забрать чужой профиль нельзя — и `404` здесь может означать в том
числе это.

## После привязки

Если в карточке было `hasCrmAccount: true`, у человека есть вход в саму CRM —
можно показать кнопку «Открыть ErkinAI». Это уже работающий сквозной вход, см.
`docs/profichat-flutter-sso-guide.md` в репозитории ErkinAI: одноразовый токен
через `POST /api/integration/medcrm/webview-url/`, обмен на bearer ErkinAI.

`hasCrmAccount: false` — специалистом стать всё равно можно: у контрактного
врача карточка есть, а учётки в CRM нет.

---

## Что стоит прогнать на устройстве

* номер сотрудника ErkinAI → экран подтверждения, поля заполнены;
* посторонний номер → обычная регистрация, ни слова про CRM;
* карточка почти пустая (как в примере: нет фото, стажа, био) → вёрстка не
  разъезжается;
* совместитель с двумя карточками → выбор из списка;
* клиники нет в справочнике → шаг пропускается, роль выдаётся;
* ErkinAI недоступен → регистрация проходит как обычная;
* повторный вход уже специалистом → `erkinaiSpecialistOffer` пустой.
