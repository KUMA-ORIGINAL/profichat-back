# Telegram: решение по заявкам кнопками + алерты об ошибках

## 1. Одобрение/отклонение заявки из Telegram

Уведомление о новой заявке специалиста теперь приходит с инлайн-кнопками:

```
✅ Одобрить   ❌ Отклонить
```

- **Одобрить** — заявка переходит в `accepted`, пользователю выдаётся роль специалиста
  (профессия/организация из заявки) и уходит пуш «Ваша заявка одобрена!».
- **Отклонить** — карточка заменяется списком причин: 4 готовых, «✏️ Своя причина» и «⬅️ Назад».
  После выбора заявка переходит в `rejected` с причиной, пользователю уходит пуш
  «Заявка отклонена» с причиной.
- «✏️ Своя причина» — бот присылает сообщение с `force_reply`; ответьте на него текстом,
  этот текст станет причиной отказа (ждём ответ 15 минут).
- После решения кнопки убираются, а в карточку дописывается кто и когда решил.
- Повторное нажатие по уже рассмотренной заявке ничего не меняет — приходит алерт
  «Заявка уже рассмотрена».

Логика решения общая с админкой (`account/services/application_review.py`), поэтому
изменение статуса в админке даёт тот же результат, включая пуш при отказе (раньше его не было).

### Настройка

1. Переменные окружения:

   ```
   TELEGRAM_BOT_TOKEN=<токен бота уведомлений>
   TELEGRAM_CHAT_ID=<id чата, куда идут уведомления>
   TELEGRAM_THREAD_ID=<id топика, если супергруппа с топиками>
   TELEGRAM_ADMIN_WEBHOOK_SECRET=<длинная случайная строка>
   # опционально:
   TELEGRAM_WEBHOOK_SECRET_TOKEN=<строка, её же Telegram пришлёт в заголовке>
   ```

2. Зарегистрировать webhook (URL должен быть доступен по HTTPS):

   ```bash
   python manage.py set_telegram_admin_webhook
   ```

   Команда ставит webhook на `POST /api/integration/telegram/admin/webhook/<secret>/`
   с `allowed_updates=["message","callback_query"]`. Снять: `--drop`, свой хост: `--base-url`.

3. Бот должен быть участником чата. Для групп у бота должен быть выключен privacy mode
   (`/setprivacy` → Disable у @BotFather), иначе он не увидит ответ с причиной отказа.

### Доступ

Решать по заявкам может любой участник рабочего чата — проверяется только то, что нажатие
пришло из чата `TELEGRAM_CHAT_ID`. Нажатия из любого другого чата отклоняются
(«Нет прав на рассмотрение заявок») и пишутся в лог с указанием chat_id и user_id.
Кто именно принял решение, видно в карточке заявки и в логе (`Application N approved by @username`).

Если уведомления и авторизация работают на одном боте (`TELEGRAM_AUTH_BOT_TOKEN` не задан),
webhook авторизации сам распознаёт нажатия по заявкам и передаёт их этому обработчику —
отдельный webhook в этом случае не нужен.

## 2. Ошибки в Telegram (как Sentry)

`common.telegram_logging.TelegramErrorHandler` подключён в `LOGGING` к `root` и `django.request`
на уровне `ERROR`. Любой `logger.error/exception` и необработанное исключение (500) уходят
в Telegram: уровень, окружение, логгер, файл:строка, метод и путь запроса, пользователь,
тип исключения, сообщение и хвост трейсбека.

Включение:

```
TELEGRAM_ERROR_ALERTS_ENABLED=True
TELEGRAM_ERROR_CHAT_ID=-1001234567890   # по умолчанию TELEGRAM_CHAT_ID
TELEGRAM_ERROR_THREAD_ID=               # отдельный топик под ошибки
TELEGRAM_ERROR_ENVIRONMENT=prod
TELEGRAM_ERROR_DEDUPE_SECONDS=300
TELEGRAM_ERROR_MAX_PER_MINUTE=20
```

Особенности:
- отправка в фоновом потоке — запрос не блокируется;
- одинаковые ошибки (логгер + файл + строка + шаблон сообщения) не дублируются чаще
  `TELEGRAM_ERROR_DEDUPE_SECONDS`, число подавленных показывается в следующем алерте;
- общий лимит `TELEGRAM_ERROR_MAX_PER_MINUTE` на процесс защищает от шторма;
- логи самого отправщика и HTTP-клиента игнорируются, чтобы не было рекурсии;
- Sentry не отключается — работают оба канала.
